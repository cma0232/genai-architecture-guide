# RAG Architecture Pattern

*Ground model responses in selected private, domain-specific, or current evidence.*

<ReadingTime minutes={8} />

## Why RAG Exists

Retrieval-augmented generation separates what the model learned during training from evidence selected at request time. It is useful when answers must depend on private documents, frequently changing information, or traceable sources.

<MiniFlow>{`Question → Query transformation → Retrieve candidates → Rerank → Assemble context → Model → Grounded answer + citations`}</MiniFlow>

## RAG Has Two Pipelines

| Pipeline | Main work | Typical failures |
|---|---|---|
| **Indexing** | Parse, chunk, enrich metadata, embed, and index documents | Bad chunk boundaries, stale index, missing access controls |
| **Query-time** | Rewrite query, retrieve, filter, rerank, assemble evidence, generate | Wrong evidence, too much context, unsupported answer |
