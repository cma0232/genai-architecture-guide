# Runtime Guardrails and Recovery

*Use deterministic controls to constrain actions and recover safely when dependencies fail.*

<ReadingTime minutes={6} />

## Guardrails Belong at Multiple Layers

- **Input controls:** size limits, file scanning, data classification, and abuse detection.
- **Context controls:** source labeling, tenant isolation, secret filtering, and retrieval allowlists.
- **Output controls:** schema validation, citation checks, policy checks, and safe rendering.
- **Action controls:** authorization, allowlisted tools, parameter constraints, spend limits, and approvals.

No single filter is sufficient. Defense in depth assumes that one control may fail and another must still contain the impact.

## Least Privilege and Zero Ambient Authority

Give each request the minimum capability needed for the current step and the shortest useful lifetime. Do not place broad credentials in prompts or give every tool access to every resource. Bind delegated credentials to user identity, tenant, action, resource, and expiration.
